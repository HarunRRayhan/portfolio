# Batch One Implementation Plan

**Goal:** Apply the eight audit recommendations approved in conversation on September 30, 2026.

**Architecture:** Keep Laravel/Inertia and the current visual design. Consolidate SEO metadata ownership, generate responsive local covers at build time, defer directory media without changing badge destinations, reuse accessible UI primitives, and isolate operational recovery by service.

**Scope:** Batch one only. Public SSR expansion, sitemap dates, video schema, release serialization, application-cache startup changes and article interaction redesign remain outside this batch.

## Tasks

- [x] SEO: one keyed head/schema owner on hard loads and Inertia navigation; sponsor server metadata. Verify PHP responses, homepage SSR, and browser navigation.
- [x] Blog media: build local WebP variants at 480/960px; preserve original/external fallbacks; first visible image eager/high priority. Verify generated dimensions and browser-selected sources.
- [x] Directory badges: keep approved markup/destinations, defer offscreen image requests and stop offscreen animation. Verify links exactly once and image loading near viewport.
- [x] Contact and newsletter: keyboard-selectable services; accessible modal focus, Escape, restoration. Verify local browser interaction.
- [x] Navigation and contrast: desktop disclosure toggling/dismissal, named account control, valid consultation link markup, accessible pricing contrast. Verify desktop/mobile.
- [x] Recovery: never mutate PostgreSQL in response to a public endpoint failure; redeploy only a diagnosed failing application service. Verify workflow guards.
- [x] PR checks: build, PHP, browser and PostgreSQL concurrency CI jobs. Required-check enforcement is a separate repository setting and will be reported accurately.
- [x] Health: bounded database/readable asset checks, scheduler heartbeat, release identity. Verify success, dependency failure, absent/stale heartbeat, and rollout readiness separation.

## Verification

Run targeted regressions, `npm run build`, PHP suite, browser suite against an isolated local SQLite database, and isolated PostgreSQL tests when Docker is available. No production forms or payments. Review all changes before completion. This implementation does not by itself deploy production.

## Review focus

- Head correctness across SSR hydration, back/forward and pages without SEO payloads.
- No remote fetches or arbitrary-path access in image generation.
- Badge destinations and accessible names retained once each.
- Scheduler outages must not prevent a healthy web deployment becoming ready.
- Failure diagnosis must not trigger database mutation or schema-incompatible rollback.

## Progress

Initial source baseline merged with origin/main (published Products changes preserved). Independent file ownership assigned to existing SEO, UI and operations agents; root owns image performance and integration verification.

Performance validation: image generator regression passed, including versioned filenames and EXIF orientation; PHP image fallback tests passed (2 tests, 8 assertions). Browser checks verify the lead cover uses responsive candidates, footer media waits until approached, and missing thumbnails fall back to same-origin originals. Active local covers total 317,834 bytes at 480px versus 2,911,609 bytes for their originals (35 current covers; 89% smaller). External images retain originals. Native lazy loading defers badges but does not eliminate their third-party requests when approached.

Full PHP validation: 499 cases, 2,849 assertions, no failures; four existing notices and three PostgreSQL-only skips. All three skipped cases passed separately against disposable PostgreSQL17 (11 assertions), including booking concurrency and the real two-second SQL timeout; container removed.

Built SSR metadata, image tests, shell syntax, ShellCheck and diff checks passed. Independent review found no unresolved correctness issues. Review fixes retained older CDN thumbnails and added explicit original-image fallback during separate origin/CDN rollouts. Frontend build passed.

Browser integration: all 35 cases verified against the final build: 34 in the full run and the idle-dialog case separately using the real one-minute timer. The simulated clock diverged from native browser animation time; the test now uses real idle time. The three image cases were rerun successfully after improving screenshot capture, and mobile/desktop screenshots were inspected. No production services, credentials, repository branch settings or payments were changed.
